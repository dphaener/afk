# Glossary

Terms afk uses. Each line comes from `docs/PLAN.md` or the plugin docs under `plugins/afk`. Add a term once; do not rewrite existing lines.

- **Session**: one `claude "/afk:go --session {name}"` process on its own PTY in its own git worktree, with state under `.afk/{name}/`.
- **Session host**: the background `afk _host` process that owns a session's PTY and outlives every UI attached to it.
- **Conductor**: the skill that runs a session's whole lifecycle (plan, execute, review, ship) and records progress in `status.json`.
- **Work plan**: the per-task plan at `.afk/plans/{session}.md`, with waves, `(W1.T2)` task ids and seven subsections per task. Not the master plan.
- **Master plan**: `docs/PLAN.md`, the project-wide plan whose tasks (`T1.1`, `T2.2`) each become one session.
- **Wave**: a group of work-plan tasks that can run in parallel because none depends on another in the same wave.
- **Task agent**: the sub-agent that implements one work-plan task and saves its evidence.
- **Verifier**: an agent that checks a task agent's finished work and, on PASS, marks the task done.
- **Check**: one of the three review passes, `compliance` (including scope), `quality` and `qa`, each returning findings and a verdict.
- **Critic**: the adversarial agent run only on a check with a blocker or major finding, which confirms, downgrades or rejects those findings.
- **Verdict**: the outcome in `.afk/{session}/review-verdict.md`, APPROVE or REJECT, computed from the findings left after the critics.
- **QA scenario**: a task's hands-on test written as tool, steps, expected result and an evidence path.
- **Evidence**: the output a QA scenario saves under `.afk/{session}/evidence/`, so a reviewer can see it ran.
- **Park**: to stop a task because only the owner can do something, setting `awaiting_input` (and, from T1.2, adding an inbox item) rather than guessing.
- **Ledger**: `.afk/build/ledger.json`, the daemon's record of each master-plan task's status; the daemon is its only writer.
- **Inbox**: `.afk/inbox/{id}.json`, the items an agent or the daemon raises for the owner (questions, env vars, external actions); planned for T1.2.
- **Case**: the fifth field of a QA scenario, `happy` for the normal path or `failure` for an error path such as invalid input or a missing file.
- **Failure scenario**: a QA scenario whose case is `failure`; every work-plan task needs one unless it carries a failure waiver.
- **Failure waiver**: the line `No failure case: {reason}` in a task's QA Scenarios, for a task with nothing that can fail (docs only, a rename).
- **Exploratory QA**: the bounded part of the hands-on QA check that follows the scenarios: tasks tried together, then the edge cases that apply to the change.
- **Detach**: a client leaving a session on purpose (ctrl-\ in `afk attach`, or closing a dashboard pane); the session keeps running.
- **Steal**: a second client connecting to a session host, which takes the session from the client already attached.
- **Dropped**: a client's connection ending without the host saying the session ended; the session may still be running.
- **Project config**: `afk.toml` at the root of a project's main checkout; hand-edited TOML that names the master plan and, later, the ship and notification settings.
- **Main checkout**: the project directory that holds the repository's `.git` directory, as opposed to a session's worktree; the daemon's state and the ledger live under its `.afk/`.
- **Ready**: a master-plan task that is `pending` in the ledger with every dependency satisfied, so it could run now.
- **Next task**: the one task the build loop would start now, chosen from the ready tasks in plan order, or the reason there is none.
- **Superseded**: a ledger status for a task kept in the master plan only as history; its entry lists the tasks that replace it, and a dependency on it waits for all of them.
- **Seeding**: recording an existing project's finished tasks in the ledger by hand with `afk ledger set`.
- **Usage window**: one of the subscription's limits that fills up and resets on a schedule: the session window, the weekly window, or a weekly window for one model.
- **Usage probe**: the zero-cost agent CLI call that reports how much of each usage window is spent and when it resets.
- **Usage snapshot**: one probe's result (windows, reset times, whether extra usage is on), kept per machine in `usage.json`.
- **Extra usage**: paid overage beyond the subscription; afk refuses to run while it is on.
- **Governor**: the pure decision that turns a usage snapshot into one action: run, launch nothing new, pause, hold, or refuse.
- **Inbox item**: one JSON file in the inbox, written only by `afk inbox add` (or, later, the daemon), with a kind, a title and whether it blocks.
- **Kind**: what an inbox item is: `question`, `env_var`, `external_action`, `verification`, `failure` or `notice`.
- **Blocking**: an inbox item the task cannot go on without; the task parks until the owner answers it.
- **Open**: an inbox item nobody has answered yet.
- **Assumed**: on a non-blocking question, the answer the agent went ahead with instead of waiting.
- **Main checkout**: the project's original folder, as opposed to a session's worktree; `.afk/inbox/` lives there.
- **Token ledger**: `.afk/log/tokens.jsonl` in the project's main checkout, one line per task, phase, role and model, recording how many tokens that part of a task used.
- **Weighted cost**: one number for a set of model calls, `input + 5×output + 1.25×cache_write + 0.1×cache_read`, in input-token equivalents; a proxy from API price ratios.
- **Token record**: one model call's usage as a provider reports it: when, which model, which role and phase, and the four token counts.
- **Role**: who made a model call inside a session: `conductor`, `planner`, `research`, `crucible`, `task`, `fix`, `verifier`, a `review:` check, `critic`, or `unknown`/`other` when it cannot be told.
- **Transcript**: the file an agent CLI keeps of one conversation, one JSON object per line; the source of token records.
- **Start-up context**: everything an agent is sent before it does anything: the system prompt, tool definitions, the skills list, connector listings and `CLAUDE.md`. It is the size of the agent's first call.
- **First call**: an agent's first model call; its input is the start-up context plus the prompt it was given.
- **Agent definition**: a file under `plugins/afk/agents/` that names an agent type and the tools it may use, so an agent starts with only what its role needs.
- **Agent type**: the name a spawn uses to pick an agent definition; a spawn with no type, or a type the session does not know, gets the default agent with every tool.
- **Build loop**: the daemon's repeated pass over each project: look at what is on disk, decide one thing to do, do it, wait for the next tick.
- **Daemon**: `afk daemon`, the always-on process that runs the build loop; it keeps nothing in memory that is not on disk, so it can be killed and restarted at any point.
- **Tick**: one pass of the build loop over every project, every few seconds.
- **Unattended mode**: the agent CLI's permission mode that never stops to ask, named on the command line when the daemon starts an agent.
- **Unattended preflight**: the check, before the daemon starts an agent, that this machine can run unattended mode without a dialog; when it fails an inbox item says what to do and nothing starts.
- **Stall**: a session that has been asking something at the terminal for longer than the stall limit with no inbox item explaining why.
- **Pause flag**: `.afk/build/paused`, written by `afk pause`; while it exists the daemon starts no new task for that project.
- **Decision log**: `.afk/log/decisions.jsonl`, one line for every decision made in the loop and who or what made it.
- **Machine config**: `config.toml` in afk's config folder, listing the projects the daemon runs and its timings; one per machine.
- **Local config**: `afk.local.toml`, laid over `afk.toml` key by key and never committed; where private values go.
- **Un-park**: to return a parked task to `running` once every item it waited for has been answered.
- **Ship**: what the daemon does with a finished session: push the branch, open a pull request, wait for CI, merge, check the deploy and clean up.
- **Ship state**: how far a task's ship has got (`committed`, `pushed`, `pr_open`, `handed_back`, `ci_green`, `merged`, `deploy_healthy`, `stopped`), saved in the ledger before the step that leaves it.
- **Hand-back**: sending a failed CI run back to the session that wrote the code, by typing one line into it that points at a file describing the failure.
- **Stop the line**: after a merge whose deploy never became healthy, the daemon starts nothing more for that project until the owner runs `afk resume`.
- **Owner task**: a master-plan task whose title carries `(owner)` or `(owner; …)`; the daemon never starts an agent for it and asks the owner to confirm it in the inbox.
- **Ledger init**: `afk ledger init`, which creates a project's ledger, optionally marking the tasks already finished; without a ledger the daemon starts nothing.
- **Required-env check**: before a merge, looking in the branch's changes for a newly required environment variable, and parking until the owner has set it.
- **Attached**: a client the session host has registered as the session's current client; a connection the host has accepted but not yet registered is not attached.
- **Stress run**: running one test or a whole test package many times in a row, with and without CPU load, to find a test that fails only sometimes.
- **Flaky test**: a test that sometimes fails although nothing it checks is broken.
- **After-merge command**: the shell command a project names in `[ship] after_merge`; the daemon runs it once in the main checkout after a merge, before it checks the deploy.
- **Run record**: `.afk/build/after-merge.json`, which says for which task and merge the after-merge command started and how it ended, so it is never run twice.
- **Binary identity**: the size and modification time of the daemon's own program file, noted at start; when they change on disk the daemon stops between passes so the service manager starts the new version.
- **Wedged**: a session whose agent is still running but has stopped answering; the host notices by asking the agent's screen to repaint and getting nothing back.
- **Client-less probing**: a session host checking for a wedge when nobody is attached, switched on with `--probe-unattached` for unattended sessions.
- **Restart ladder**: how a host stops a wedged agent, one signal at a time from polite to forced, before starting it again in the same conversation.
- **Relaunch**: starting a new host for a session whose host is gone, for example after the machine restarted.
- **Recovery**: one automatic restart or relaunch of a running task's session by the daemon.
- **Restart cap**: `max_restarts`, the most recoveries the daemon makes for one attempt at a task before it parks the task with an inbox item.
- **Backoff**: the wait before each recovery after the first, starting at `restart_backoff` and doubling each time.
- **Continue prompt**: the session's resume command, typed by the daemon once after a recovery so the agent carries on from where its files say it was.
- **Focus**: where the dashboard sends keys and clicks: the list of sessions, or the right side. There is only one, and the screen shows which.
- **Right side**: the dashboard's larger pane beside the list; it shows the selected row's agent or its overview.
- **Agent view**: the right side showing the selected session's live terminal.
- **Overview**: the right side showing the selected session's summary (plan, progress, review) instead of its terminal; a row with no live agent always shows it.
- **Walk-through**: driving a built afk by hand (through tmux) in a throwaway repository and saving the screens, to check behaviour the tests only describe.
- **Usage pause**: the daemon stopping a running session's agent because a usage window is nearly spent (or extra usage is on), and starting it again in the same conversation after the reset.
- **Wake time**: the earliest moment a session paused for usage may be started again, usually one minute after the full window resets.
- **Hold**: the governor's answer when it has no recent usage reading: nothing new starts and a running session is left alone.
- **Rate-limit marker**: `.afk/{session}/.rate-limited`, written by a hook when the agent CLI stops because of a usage limit; the daemon reads it and pauses the session.
- **Login check**: the daemon asking the agent CLI, about once an hour, whether it is still logged in; logged out means nothing new starts.
- **Spike**: a short hands-on experiment run before the work is planned, to find out how something really behaves.
- **Web page**: the small site `afk daemon` serves for status, usage, the inbox and the pause and resume buttons; off until a web token is set.
- **Web token**: the shared secret in `[web] token`; every request to the web page must carry it, as a cookie, a bearer header or a one-time `?token=` visit.
- **Loopback**: an address only this machine can reach (`127.0.0.1`, `::1`, `localhost`); the web page's default, and the only kind allowed without a token.
- **Public URL**: `[web] public_url`, the address the owner reaches the web page at from outside; used to put a link to an inbox item in a notification.
- **Project summary**: what the web page shows for one project: current task and phase, tasks done over total, last ship result, and whether it is paused or stopped.
- **Build tab**: the dashboard tab that lists the master plan's tasks with their ledger status; it is about the project, not the selected session.
- **Inbox overlay**: the dashboard's box, opened with `i`, that lists the project's inbox items, shows one in full and takes an answer.
- **Usage segment**: the part of the dashboard's header that shows the governor's last decision and the tightest usage window.
- **Tightest window**: the usage window with the highest percentage used, the one that will hold the build back first.
- **Build snapshot**: everything the dashboard shows about a build, read from the main checkout's files in one go on each refresh.
- **Runbook**: `docs/runbook-vm.md`, the step-by-step for getting a project ready on the always-on machine, with each step marked as the machine's or the owner's.
- **Project prerequisites**: what a project's own checks need installed on the machine (for nebari: Ruby, PostgreSQL, libvips, a headless Chrome), as opposed to what afk needs.
- **Capped API key**: a separate provider key with a low spend limit, used only for a project's live smoke checks and fixtures, kept in the project's local settings and never in the agent's environment.
- **Tunnel**: the owner's private route from a phone or laptop to the web page on the VM (a VPN or a reverse proxy); the page itself stays on loopback.
- **Restore drill**: restoring a database backup somewhere safe to prove the backup works, done once before deploys run unattended.
- **Set-up branch**: `afk-setup`, the local branch in a project that holds its `afk.toml`, ignore lines and CI change until the owner pushes and merges it.
- **Supervised run**: the first task afk runs in a project with the owner watching in the dashboard from launch to a healthy deploy, before the daemon is left to run by itself.
- **Retrospective**: the write-up after a supervised run of what needed a human, the cause of each, and the task's token use.
- **Plan format**: the written rules for a master plan (`plugins/afk/skills/master-plan/plan-format.md`): its sections, how a milestone and a task are written, and what the daemon reads.
- **Checker**: `afk plan lint`, which reads a master plan the way the daemon does and lists everything wrong with it, not only the first problem.
- **Finding**: one thing the checker reports about a master plan: a level, a line, the task it is about, the rule it broke and a message.
- **Error (checker)**: a finding the daemon would refuse the plan for, or would misread; `afk plan lint` exits 1 when there is one.
- **Warning (checker)**: a finding the daemon can live with but a reader would miss, such as a task with no Goal.
- **Milestone**: a group of master-plan tasks under one `### M<n> — Title` heading, with one outcome.
- **Open question**: a row of a master plan's Open questions table that has not been answered yet; its "Needed by" cell names the tasks that need the answer.
- **Slicing rule**: how a master plan is cut into tasks: each task is a thin, complete path through every layer the change touches that can be shown working by itself.
- **Owner profile**: `profile.toml` in afk's config folder, beside the machine config; where the owner states once how they build and host things, for every planning session to read.
- **Profile entry**: one `[[entry]]` of the owner profile: a topic, a value, a strength, and optionally the kind of project it applies to and a reason.
- **Topic**: what a profile entry is about, such as the database or hosting; topics compare with case and spacing ignored.
- **Strength**: whether a profile entry is a `rule`, which a plan must follow, or a `default`, which a plan uses unless the project says otherwise.
- **Kind (project)**: the sort of project a profile entry applies to, such as `web-app`, `cli` or `library`; an entry with no kind applies to every project.
- **Rule file**: an existing house-rule document the owner profile points at, to be read by a planning session and never copied into the profile.
- **No preference**: a profile value that means the owner has no fixed choice on a topic, so the planning session should recommend one and say why.
- **Secret check**: the test `afk profile set` and `afk profile check` apply to refuse a value that looks like a key or token.
- **Planning session**: the attended agent session `afk plan` starts in a project's main checkout to turn the owner's idea into a checked first draft of the master plan; its host is the session named `master-plan`.
- **Plan phase**: how far a planning session has got: `brief`, `survey`, `model`, `rounds`, `slices`, `draft`, `check`, `design`, `review` or `approved`.
- **Brief**: the owner's request for a project, saved word for word in `.afk/plan/brief.md` and never edited afterwards.
- **Survey**: what a planning session read before asking anything (the owner profile, its rule files, the folder), with the profile entries that apply.
- **Product question**: a planning question about what to build, asked with options and one recommendation so that "yes" accepts it.
- **Setup fact**: something about how the project is named, hosted or built (accounts, addresses, stack) that comes from the owner profile or the owner and is never guessed.
- **Round**: one batch of planning questions, holding every question whose prerequisites are settled.
- **Slices**: the proposed task breakdown the owner confirms before the master plan is drafted, saved in `.afk/plan/slices.md`.
- **Gate (plan phase)**: what must be on disk before a planning session may leave a phase; `afk plan advance` checks it.
- **Planning marker**: the empty file `.afk/master-plan/planning`, which makes every start of that session's host run the planning skill.
- **Reserved name**: a session name afk keeps for itself (`plan`, `master-plan`), which `afk new` refuses.
- **Guarded patch**: a change to a master plan given as an old text and a new text; the old text must be in the plan exactly once, and nothing is written if the change would add a checker error.
- **Entry (task)**: a task's part of a master plan, from its heading to the line before the next heading.
- **Held task**: a task that is `running` or `shipping` in the ledger; a guarded patch may only add an Amended line to its entry.
- **Amended line**: a dated line added to a plan section or task entry (`Amended 2026-10-13 …`) that says what changed, leaving the original text as it was.
- **Change session**: a planning session on a project that already has a plan, in one of the modes `extend`, `amend` or `reconcile`.
- **Extend**: the change session that adds a new milestone to a plan.
- **Amend**: the change session that adds, splits or supersedes one task of a plan.
- **Reconcile**: the change session that reads a named document against the plan and brings the plan in line with it.
- **Split**: replacing one task with two or more lettered tasks; the old task stays in the plan as history and is marked superseded in the ledger.
- **Letter suffix**: the letter on a task id such as `T2.2a`, given to a task that must run between two existing ones, so no id is ever renumbered.
- **Changes list**: `.afk/plan/changes.md`, where a change session lists each patch it made; a change session cannot leave its draft phase without it.
- **Plan-changes branch**: `afk-plan-changes`, the branch a guarded patch is committed to when the project sends plan changes through a pull request.
- **Follow-up prompt**: a file `docs/design-followup-<n>.md` written by a reconcile, saying what the design must change to fit the plan.
- **Design phase**: the phase of a new planning session, between `check` and `review`, that hands the look of the project to the owner's design tool; only a project whose interface answer is yes has it.
- **Interface answer**: the answer to the round-one question with the id `r1-interface`, which starts with `yes` when the project has screens a person looks at and `no` when it does not (a command line, an API only, none).
- **Design brief**: `docs/design-brief.md`, the prompt the planning session writes for the owner to take to a design tool; it says what the product is, which screens the plan implies and what to hand back.
- **Design system**: `docs/design-system.md`, the one document the design tool hands back, holding tokens, components and screens.
- **Design task**: the owner task titled `Design system (owner)` in a plan's first milestone; every task that builds interface waits for it.
- **Precedence rule**: where the plan and the design system disagree, the plan wins on behaviour and the design system wins on looks.
- **Failed turn**: an agent turn ended by an API error (a lost connection, a server error, an overloaded service), which leaves the session idle at its prompt with its host alive.
- **Failed-turn marker**: `.afk/{session}/.turn-failed`, one line with the time and the reason, written by the `StopFailure` hook for a failure worth trying again and removed by the next prompt or a normal stop.
- **Wake**: the daemon typing a session's resume command into it, after a failed turn or a stall, without restarting its host; counted in the ledger as `wakes`, apart from `restarts`.
- **Needed by**: the column of a master plan's Open questions table that names the tasks which need the answer; a row that names no task there holds nothing.
- **Answered marker**: the text `**Answered <date>:** <the answer>` inside a row's Question cell, which is what makes an open question answered.
- **Question hold**: the daemon parking the next ready task, with nothing started for it, because an open question names it in "Needed by".
- **Question item**: the blocking inbox item, titled `Open question: …`, that the daemon raises once for each open question holding a task; the owner's answer is written into the plan.
- **Follow-up item**: the blocking inbox item, titled `Put the answer in the plan: …`, raised when an answer could not reach the plan in the main checkout, for example because plan changes go through a pull request.
- **Approve**: the owner's terminal command (`afk plan approve`) that turns a reviewed plan into a build: it commits the planning documents, creates the ledger, adds the project to the machine config and sets the plan phase to `approved`.
- **Planning documents**: the files a planning session writes and the approve commits: the master plan, `afk.toml`, `.gitignore`, `CONTEXT.md`, the design brief and the agent instruction files.
- **Project list**: the `[[project]]` entries of the machine config, which are the projects the daemon builds; edited with `afk project` and read again by the daemon on every pass.
- **Review list**: `plan-reviews.json` in afk's state folder, naming the projects whose plan is waiting for approval, so the web page can show a plan before its project is in the project list.
- **Plan view**: the web page for one project's master plan. It shows the plan rendered, the checker's counts and findings and the open questions, and it can approve a new plan at review behind a confirm.
- **Plan line**: the one-line planning status (the planning session's mode, phase and what it waits for) shown on the dashboard and on the web page, worded by the same function.
- **Project switcher**: the dashboard's list of projects, opened with `p`; it shows the listed projects, the start-up project and any found under the search folders, one row each.
- **Listed project**: a project in the machine config's project list, as `afk project list` prints it; the switcher shows it under the name given there.
- **Start-up project**: the project `afk dash` was started in (or named with `--project`); it is always in the switcher, listed or not.
- **Search folders**: the folders the dashboard looks under for more projects (`search_roots`); until T6.2 they are set in `config.json`.
- **Dash table**: the `[dash]` table of the machine config, holding the dashboard's search folders, how often it searches and how deep; the daemon ignores it, and a bad value in it stops nothing but the folder search.
- **Old-settings notice**: what `afk dash` says once per start when a `config.json` is still in afk's config folder: the file is no longer read, and here are the `[dash]` lines to add to `config.toml`.
- **Leader key**: the one key (ctrl+]) that, pressed in the Agent level of the dashboard, says the next key is a dashboard key and not typing.
- **Actions dialog**: the list the leader key used to open; replaced by the Key strip and the Actions search.
- **All-projects screen**: one dashboard screen with a row per project the daemon builds, showing its current task, build state and inbox count.
- **Chat view**: the web page's screen that shows a planning session as messages, with a reply box and a button per offered option; it is never the session's terminal, and a reply from it takes the session from the dashboard for a moment.
- **Pause key**: `p` at the Project level of the dashboard, which pauses the active project's build as `afk pause` does: a running task finishes and nothing new starts.
- **Resume key**: `p` again in the dashboard when the build is paused or stopped, which resumes the project's build as `afk resume` does, and clears a stopped line.
- **Inbox segment**: the part of the `afk dash` header that counts the active project's open inbox items and how many of them are blocking a task.
- **Project location**: the owner profile entry naming the folder under which the dashboard creates a new project typed by name.
- **Plan line**: the one line in `afk dash` (on the `master-plan` session's overview and the Build tab) that says the planning session's mode, phase and what it waits for.
- **All-projects screen**: the `afk dash` screen (the first level, reached with `esc` from a project) that lists every project the daemon builds, one row each, the ones needing the owner first.
- **Project row**: one line of the all-projects screen for one project: its name, tasks done of the total, its state, its inbox counts and whether its plan waits for approval; built by `internal/projectrows`.
- **Tokens overlay**: the `afk dash` overlay (`t`, on the Build tab) that shows the selected task's token use as `afk tokens <task>` prints it, with a narrower table when the window is narrow.
- **Short total**: the selected Build tab row's weighted token total, shortened (`2.9M weighted`), shown only when the row has room.
- **Live part**: one of the things an open web page updates by itself when its files change: `inbox`, `ledger`, `pause`, `sessions`, `planning` or `usage`. Named in the events of the page's `/events` stream.
- **Planning chat**: a project's open planning session read as messages (the agent's and the owner's) plus its state (`none`, `working`, `waiting_for_text`, `waiting_for_choice`, `unknown`), served at `GET /api/p/<project>/plan/chat` and built by `internal/planchat`. The web page draws it at `GET /p/<project>/plan/chat` (the **Planning chat** page), with links from the project's nav, the plan line and the planning session's row.
- **Plan reply**: the owner's answer to the planning chat, sent with `POST /api/p/<project>/plan/chat`: typed text (sent as one bracketed paste and Enter), or one chosen option per pending question (sent as the keys the agent's question dialog takes), or an own answer (see **Own answer**). The planning chat page posts it as an ordinary form (`text`, `choice-<i>`, `other`) to `POST /p/<project>/plan/chat`.
- **Taken over**: what the dashboard says when another client, such as a plan reply from the web page, takes a session's one client slot from its pane; enter reopens the pane.
- **Needs you**: the first group on the web page's home screen and the dashboard's all-projects screen, holding the projects that wait on the owner (and a plan waiting for approval); the rest are under Everything else.
- **Confirm sheet**: the native dialog the web page opens before Pause or Resume, with a safe choice that changes nothing; its no-JavaScript twin is the page `GET /p/<project>/confirm/{pause|resume}`.
- **Toast**: the short notice on a project's page after a change, read from a whitelisted `?done=` code and gone after five seconds.
- **Live indicator**: the bar's word for the page's stream: Live, Working (the stream is up and a part says afk is busy on a task) or "Can't reach afk, retrying".
- **Inbox screen**: the web page's own page for a project's inbox, `GET /p/<project>/inbox`, listing open items blocking first; an answer returns to it.
- **Confirm field**: the `confirm=yes` form field (or `{"confirm": true}` in JSON) a pause or resume POST must carry; without it the POST changes nothing.
- **Sessions screen**: the web page's list of a project's sessions, `GET /p/<project>/sessions`, with each session's phase, progress, review verdict and whether it waits for you, and a badge for the rows that are not ordinary sessions.
- **Session screen**: the web page's read-only overview of one session, `GET /p/<project>/sessions/<name>`; its terminal is opened from `afk dash` or `afk attach`.
- **Session actions**: Clean, Restart and Label on a session's screen of the web page, and Start a new autonomous session… on the sessions screen; each asks first, and the page starts only autonomous sessions.
- **Own answer**: the owner's answer to a planning session's open question in their own words instead of one of the offered options, sent as `{"other": "..."}`; only for one single-select question, and only where the agent's dialog has keys afk has seen work.
- **Being-planned list**: `being-planned.json` in afk's state folder, naming the projects whose new plan was started from the web page, so the page keeps them on the overview, marked as being planned, until the plan is approved or its planning session is gone.
- **Planning wait**: one stretch of time in which a planning session waits for the owner (a question to answer, or a reply to type); afk sends one notification per planning wait, and a new one starts only after the owner answers.
- **Plan-waits file**: `plan-waits.json` in afk's state folder, where the daemon records which planning waits it has already sent a notification for, so a restart does not send them again.
- **GitHub question**: the web page's yes-or-no after it makes a new folder, offering a private GitHub repository named `<account>/<folder>` for it; No is checked, the question is asked only for a folder the page has just made, and nothing is pushed.
- **Pending change**: a project the web page has just added or removed that the daemon has not yet picked up from `config.toml`; the overview says so until its next pass.
- **Leader setting**: the `leader = "<key>"` line in the `[dash]` table of `config.toml` that picks the dashboard's leader key; a key the dashboard cannot use falls back to ctrl+] with a line in the header saying what to fix.
- **Back row**: on the web page above 760px wide, the row under the top bar holding the back chevron and the page title, as the phone bar does; absent on the overview and the error page.
- **Web password**: the owner's password for the web page, set with `afk web password` and kept only as a salted hash in `web-password.json` in afk's state folder; it replaced the `[web] token` in T8.18.
- **Release build**: an afk binary built by the release workflow from a `v<semver>` tag, carrying its version; a `make install` build reports `dev` instead.
- **Install plan**: the ordered steps `afk install` works through (safety, packages, agent CLI, logins, unattended mode, plugin, git identity, project location, web page, service, check), each done, to do or cannot, worked out by `internal/install` from what it found on the machine.
- **Machine risk**: how safe a machine is to run afk on: `dedicated`, `vm`, `personal` or `unknown` (treated like personal).
- **Safety screen**: the first screen of `afk install`, before anything changes: it says that afk's agents run with permissions bypassed and that afk belongs on a machine set aside for it, and on a personal computer asks the owner to type `I accept the risk`.
- **Terminal handover**: `afk install` giving the terminal to another program (`sudo`, a sign-in, `afk web password`) until it ends, so that program can ask its own questions.
- **LaunchAgent**: the file `~/Library/LaunchAgents/io.github.dphaener.afk.plist` that `afk install` writes on a Mac so launchd runs `afk daemon` in the background while the owner is logged in; the macOS counterpart of the Linux `afkd.service` user unit.
- **Bootstrap script**: `install.sh` at the top of the repository, fetched with `curl ... | sh`; it downloads a release's afk, checks its checksum, puts it in `~/bin` and starts `afk install`.
- **Next version**: what `go run ./scripts/nextversion <from-sha> <to-sha>` prints for a push to `main`: `skip` when nothing in the binary changed, `0.1.0` before the first release, otherwise the last release tag raised by the commit messages (a breaking change the major, a `feat` the minor, anything else the patch).
- **Release decision**: what `scripts/release-decide.sh <from-sha> <to-sha>` prints for the release workflow: `skip` when the commit already carries a `v*` tag, otherwise the next version.
- **Desktop back bar**: the back row in the design system's shape since T10.3, `app-bar app-bar--back app-bar--desktop` under the top bar: the back chevron, the page title and optional meta (the planning chat's phase), not sticky.
- **Review summary**: what a planning session prints when it reaches `review`, saved first to `.afk/plan/summary.md` so `afk plan status` can print it again after the session has ended.
- **Finished change session's agent**: the agent of an extend, amend or reconcile planning session that has reached `review`, saved its summary and is waiting for the owner; afk ends it (the daemon on its next pass, or the next `afk plan`) so it never blocks the next session.
- **Fix task**: a master-plan task whose title carries `(fix)` or `(fix; …)`, added by a bug-fix planning session; the daemon builds a ready one ahead of every other ready task, and a task may not be both a fix task and an owner task.
- **Fix mode**: the fifth planning mode, `afk plan fix "what is broken"`: a change session that reproduces a bug, finds its cause and adds one fix task to the plan, and changes no code itself.
- **Fixes milestone**: the standing milestone titled exactly `Fixes` that holds every fix task; the first `afk plan fix` creates it, and later fixes are added at its end.
- **Web push**: a notification the push service of a browser (Google's, Mozilla's, Apple's) delivers to a device that signed up for it, encrypted so only that browser can read it; afk sends it straight from the daemon, with no app store and no third-party account.
- **Push subscription**: what a browser hands the page when it signs up for web push: an endpoint address at its push service and two keys (`p256dh` and `auth`) used to encrypt messages for it.
- **VAPID key**: afk's own key pair that signs every push it sends, so the push service knows the pushes come from the same server the browser signed up with; afk makes it the first time and keeps it in `push-key.json`.
- **Device list**: `push-devices.json`, every push subscription signed up on this machine, with a label naming the browser and system.
- **Web app manifest**: the file `/manifest.webmanifest` that tells a browser the page can be installed as an app: its name, its icons, its colours and the address it opens at.
- **Service worker**: a small script (`/sw.js`) the browser keeps for an installed page; afk's does nothing yet and caches nothing, and T15.5 gives it the push handler.
- **Notifications page**: `/notifications`, the machine-wide web page where the owner turns notifications on or off for the device they are using and sends a test; reached from the bell on the phone bar and Notifications on the top bar.
- **This device card**: the Notifications page's card showing whether the device in hand gets notifications (on, off, blocked, or a note saying what it needs first: an `https://` address, the iPhone home screen, or another browser).
- **Send test**: the This device card's button that sends one push to this device only, to prove notifications arrive.
- **Device cookie**: `afk_push_device`, a cookie the web page sets to the id of the device a browser signed up as, so the Notifications page can mark "This device"; it never holds the device's push address.
- **Gone device**: a signed-up device whose push service answers that it no longer takes notifications (404 or 410), for example because its browser dropped the subscription; afk removes it from the device list the next time it tries to send to it.
- **Theme**: one of the dashboard's four named colour sets (`tide`, `fjord`, `paper`, `phosphor`), chosen with `[dash] theme` in `config.toml`; unset, the dashboard uses `tide` on a dark terminal and `paper` on a light one.
- **Token**: one named colour role in a theme (`bg`, `panel`, `accent`, `need`, and so on); every colour the dashboard draws is a token.
- **Title strip**: the filled first row of a dashboard pane, holding its name on the left and context on the right; it is `accent` on the pane that has the keyboard.
- **Dimming**: what the dashboard does to the screen under a dialog or overlay: every colour moves most of the way to the theme's background and bold goes, so the overlay stands out.
- **Level**: one of the dashboard's three screens, All projects, Project and Agent; `enter` goes in one and `esc` comes back out.
- **Key strip**: the small list of keys that appears in the Agent level after the leader key, naming the keys the next press can use; a key it does not list closes it and sends nothing.
- **Actions search**: the `:` box that finds every dashboard action by name, the ones with no key too; letters always type into it.
- **Keys overlay**: the `?` list of every key, level by level, built from the same table the key handling uses.
- **Running group**: the home screen's group of projects with a task running and nothing that needs the owner; it sits under the RUNNING heading, after NEEDS YOU.
- **Quiet group**: the home screen's group of projects that need nothing from the owner and are not running or finished (paused, held for usage, nothing ready, no plan); under the QUIET heading.
- **Finished group**: the home screen's group of projects that are finished and need nothing from the owner; under the FINISHED heading, last.
- **Band**: the one line of counts across the top of the home screen: each group's count, the open inbox items with the blocking ones, and usage when there is a reading.
- **Selected panel**: the part of the home screen under the rule that says what the selected project waits on, the question in full and what answering it unblocks.
- **Section**: a numbered pane inside the project view: Sessions, Build, Inbox; `tab` and `1`-`3` move between them.
- **Read-only pane**: the selected session's summary under Sessions; it never takes the keyboard.
- **Linked row**: the row in another section that belongs to the selection, filled with the strip colour and ending `◂ name`.
- **Details overlay**: the 54-column pane on the right (full width below 100 columns) that `d` opens over any level for the selected session, with the tabs Overview, Waves, Stack, Notes and Diff; `esc` goes back to where it was opened.
- **Agent band**: the line under the Agent's title strip that sums up the session (phase, task, diff, loop, host) and names the next session in the project that needs the owner.
- **Needs you**: something only the owner can move on: a session waiting on them, an inbox item that blocks a task, a plan to approve, a broken session or a gone project; the dashboard keeps them in one order across every project.
- **Next needing you**: the item after the one in view in that order; `]` goes to it and `[` to the one before, and the Agent's band names it.
- **Jump search**: the `/` box that finds any project, session or task across every project and goes there; things that need the owner come first.
- **Answer screen**: the inbox item screen of `a` and `enter` on an inbox row: the item's choices numbered `1`–`n`, a "Write my own answer" field, and a line on what happens next.
- **Activity line**: the twelve cells of a home-screen row that show how many decisions the project's loop made in each two hours of the last day.
- **This week**: the home-screen chart of the tokens every listed project used on each of the last seven days, with the usage line beside it.
- **Program status**: Rex's OSC 7501 escape sequence, by which a program tells its terminal it is idle, working, done, blocked or in error, with a short message; one report sets one record.
- **Safe insertion point**: a byte offset in a terminal output stream that is outside every escape sequence and every multi-byte character, where afk may write a sequence of its own without tearing the program's.
- **Agent status**: the last Program status report a session's own agent sent about itself (state, kind, message, when), kept by its host in `host.json` as `agent_status`.
- **Last exit**: how a session's previous agent program ended (exit code, signal, when), written to `host.json` as `last_exit` when the host restarts it in place.
- **afk status**: the Program status records afk itself sends from `afk dash` or a foreground `afk daemon`: one for the whole machine (what needs the owner) and one per project.
- **Runtime**: the way a session is run: `afk` (afk's own session host) today, Rex from T17.7. `host.json` names it as `runtime`, and everything that starts, stops, restarts, types into or opens the session goes through that runtime.
